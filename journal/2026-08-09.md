# Diagnostic rendering and review scope

The Malibu cover-letter trajectory exposed an authority-boundary failure: a semantic claim reviewer treated required salutation and closing language as unsupported CV facts, coverage repair tried to fill qualifications for which no trusted support existed, and an optional output field (`notes`) became terminal because its producer and schema disagreed. These are governance defects, not reasons to add more lexical matching or retries.

The framework now distinguishes ordinary/final rendering (a trusted publication-path operation) from diagnostic rendering (a deterministic evidence-only derivative of an already rejected Markdown candidate). The latter is hash-bound to exact persisted parent bytes and uses the typed, sortable child grammar `artifact.sequence.rejected.render.pdf` and its own sidecar, so it cannot collide with the parent's explanation or enter trusted inputs. A renderer failure is separately preserved as `.render.txt`; it never relabels the original verdict.

The authority reference now requires structural and conventional language to be classified `not_factual`, limits repairable coverage to source-backed material omissions, and requires contract fields to have consumers and consequences. This is accompanied by schema v5 run evidence, package schema v4 diagnostic-render capability declarations, persistence helpers, documentation routing, and regression tests. Legacy evidence is deliberately not rewritten.
